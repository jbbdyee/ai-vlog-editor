# 8000 환경 변수 allowlist·세션 토큰 상속 수정 — 2026-11-05 (P0-6, 완료)

승인 범위: 사전 검증 통과 시 8000 계획 재시작 최대 1회. 신규 렌더·LLM·VLM 호출, migration, 사용자 데이터 변경, 5173·8001·DB·Docker·Tailscale 변경, 커밋·Push 없음. 토큰 값은 출력·기록하지 않았다(변수 이름만 기록, 생성 파일 전체에서 값 검색 0건).

## 원인

- PowerShell `Start-Process`는 호출한 셸의 환경 전체를 자식에게 복사한다. P0-5 재시작은 Claude Code 세션의 셸에서 실행돼 PID 45336이 `CLAUDE_CODE_*`(메시징 토큰·소켓 포함), `AI_AGENT`, `CLAUDECODE`, `MSYSTEM`, `WT_*`, `SESSIONNAME` 등 16개 세션 변수 이름을 상속했다.
- 이전 수정(이름 패턴 denylist)은 `CLAUDE*`/`CODEX*`만 지워 `MSYSTEM`·`WT_*`·`GIT_*` 등 다른 세션 변수가 남는 구조였다.

## 수정 (Git 제외 `temporary/qa07-recovery/`)

- `run-8000.ps1`(SHA-256 `7eb0a488…e538`): **allowlist**로 변경. 표준 Windows 변수 33개(SystemRoot·TEMP·USERPROFILE·APPDATA·ProgramFiles 등)만 남기고 나머지를 모두 제거한 뒤 PATH를 레지스트리(Machine+User)로 다시 만들고 Docker CLI를 앞에 둔다. `LANG/LC_ALL/LC_CTYPE=C.UTF-8`만 추가한다. 남은 이름이 allowlist 밖이거나 `CLAUDE|CODEX|AGENT|TOKEN|SECRET|PASSWORD|KEY|SOCKET|SESSION|POSTGRES|CUTORY`에 걸리면 기동하지 않는다. Docker·DB revision·Ollama 점검도 필터된 환경에서 실행한다.
- 앱 설정은 상속하지 않는다: `start_server.py`가 인자로 CUTORY_*·OLLAMA_BASE_URL을 설정하고 외부 API 키를 비우며 `.env`에서 POSTGRES_*·모델 이름을 읽는다(앱이 읽는 변수는 코드 검색으로 확인). DB·Docker·Ollama·FFmpeg·글꼴 설정은 그대로다.
- `-EnvProbe` 모드와 `env_probe.py`(`469c445d…0685`): 서버 대신 같은 환경·같은 `Start-Process` 경로로 탐침을 띄워 이름만 기록하고 의존성을 확인한다. PS 5.1의 `Start-Process` 종료 코드 누락 문제를 핸들 고정으로 고쳤다.

## 격리 검증 (통과)

- 부모 셸에 토큰 변수가 있는 상태에서 `-EnvProbe`: 자식이 받은 이름 37개 = 표준 33 + PATH + 로캘 3, 금지 패턴 0건. 번들 FFmpeg/ffprobe·Docker CLI가 PATH에서 해석, Docker 엔진 29.9.2, `.env` 기반 DB 읽기 전용 연결·revision `e3a1c9d27b45`, Ollama `/api/tags`의 `gemma3:4b`, 글꼴 존재, 외부 API 키 빈 값 → 10/10 통과.
- 부정 시험: 부모에 가짜 `CUTORY_FAKE_AGENT_TOKEN`·`FAKE_SESSION_X`·`POSTGRES_PORT=1`을 넣어도 자식에서 모두 제거되고 DB는 `.env` 값으로 연결됐다. 필터 없이 탐침을 직접 실행하면 세션 변수 18개를 검출하고 실패(exit 1)했다.

## 재시작 시도 — 실패, 8000 무변경

- 사전 조건: 활성 작업 0, 8000 연결 0, DB·파일 스냅숏(17개 테이블 491행, 파일 40개) 확보.
- 10:11:31 `stop_server.py --pid 45336`이 Ctrl+C를 보냈으나 60초 안에 종료되지 않았다(exit 3). 서버는 종료 절차에 들어가지 않았고 health·렌더 VERIFIED·두 다운로드 해시·ETag, DB·파일 스냅숏이 시도 전과 동일하다. **재시작은 일어나지 않았고 재시도하지 않았다.**
- 원인(읽기 전용 확인): Claude Code 셸의 자식은 `RTL_USER_PROCESS_PARAMETERS.ConsoleFlags` bit0(Ctrl+C 무시)을 상속한다. 45336·Vite 41712·이 셸의 자식 모두 1, Codex에서 띄운 이전 13384(정지 성공)와 8001은 0. 따라서 P0-5에서 검증한 Ctrl+C 정지 경로는 이 셸에서 기동한 프로세스에 적용되지 않는다. P0-5 사전 점검에서 놓친 조건이다.
- 정지 도우미 수정 `stop_server.py`(`16384840…11b9`): 대상의 Ctrl+C 무시 여부를 읽어 무시하면 Ctrl+Break(uvicorn 0.52.4가 SIGBREAK로 정상 종료 처리)를 한 번만 보낸다. 무시하는 대상에 Ctrl+C 강제 지정은 거부한다. 강제 종료·단계적 확대는 없다.
- 격리 검증: 같은 방식(이 셸 → 숨김 `Start-Process`)으로 띄운 더미 uvicorn(8099, ConsoleFlags=1)에서 Ctrl+C 강제는 거부, 자동 모드는 Ctrl+Break → "Shutting down…Application shutdown complete…Finished server process", lifespan 종료 처리 실행, 포트 해제.
