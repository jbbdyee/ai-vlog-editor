# WEB-10 — 프로젝트 목록 및 최근 작업 화면

상태: **로컬 개발용 구현·실제 DB/API/Chrome 목록 조회 검증 완료**. Git `main`, HEAD `1a2d7d71c4c2bbdc8d01a917227cd176d7fc7843`에서 시작했다. WEB-08C를 포함한 기존 미커밋 변경과 보호 대상 백엔드 테스트 3개를 보존했고 커밋·Push하지 않았다.

## 기존 구조와 변경 이유

기존 `POST /projects`, `GET /projects/{id}`는 생성·ID 직접 열기만 제공했다. React `HomePage`에도 목록이 없었다. `Project`에는 `created_at`·`updated_at`가 있고, 소스는 `SourceVideo.project_id`, 편집 계획은 `ProjectSceneEditPlan.project_id`, 렌더 기록은 WEB-08C의 `ProjectRenderRun.project_id`로 연결된다. `updated_at`은 프로젝트 행의 수정 시각이며 모든 하위 활동의 최신 시각이라는 보장은 없으므로 UI의 ‘마지막 작업 시간’으로 쓰지 않았다. 기존 렌더 파일은 DB 기록이 아니며 목록을 위해 자동 등록하지 않는다.

## 구현

- `GET /projects?limit=20&offset=0`을 추가했다. `limit`은 1~50, `offset`은 0 이상이며 `items`와 `next_offset`을 반환한다. `created_at DESC, id DESC`로 결정적인 최신 생성순 정렬을 한다. 한 쿼리의 상관 서브쿼리로 소스 수·편집 계획 행 존재·가장 최근 렌더 행 상태를 읽어 대용량 소스/후보/렌더 관계 객체를 로딩하지 않는다. 이름이 빈 문자열이어도 그대로 반환한다. 기존 생성·상세·렌더 API 응답은 변경하지 않았다.
- React 홈은 TanStack Query로 목록을 읽고 카드 선택 시 기존 `/projects/{id}` 작업 화면으로 이동한다. 생성·ID 직접 열기도 유지한다. 빈 목록·로딩·API 오류, 20개 단위 이전/다음, 목록 새로고침을 제공한다. 빈 이름은 ‘이름 없는 프로젝트’, 렌더 기록 0건은 ‘없음’으로 표시한다. 긴 이름·UUID를 줄바꿈하며 WEB-09B 모바일 너비 규칙을 유지한다.
- 새 DB 마이그레이션·신규 렌더·기존 렌더 자동 등록은 없다. 인증·사용자 소유권 검증이 없어 이 목록은 로컬 개발 전용이다. `latest_render_status`는 실제 DB 행의 상태이며 자동 추천·영상 품질 지표가 아니다.

실제 DB 조회를 위해 활성 처리·분석·렌더 0건을 확인한 뒤 FastAPI만 새 코드로 재시작했다. WEB-08C의 `CUTORY_RENDER_PERSISTENCE_ENABLED=1`을 유지했고 PostgreSQL·Vite·Tailscale Serve는 변경하거나 재시작하지 않았다. 원본 영상·기존 렌더·GT·Manifest와 DB의 프로젝트 행은 수정하지 않았다. 기존 DB에 렌더 기록이 0건이므로, 목록에서 **완료·실패 렌더 상태를 실제 DB로 보여 주는 경로**는 아직 미검증이다. 합성 API 테스트에서 실패 상태 표시용 값은 확인했다. 프로젝트 생성은 기존 단위/Mock 회귀로 확인했으며 이번 실제 DB에 새 프로젝트를 만들지는 않았다.

## 남은 한계

`offset` 페이지네이션은 조회 사이 프로젝트가 새로 생성되면 항목이 중복·이동할 수 있다. 현재 로컬 소규모 목록에서는 허용하되 안정적인 장기 페이지 이동이 필요하면 키셋 커서를 검토한다. 목록은 프로젝트 생성일 기준이며, 하위 영상 업로드·분석·렌더를 포함한 통합 최근 활동순이 아니다. 이를 제공하려면 정확한 활동 정의와 DB 기록을 별도로 설계해야 한다. 공개 배포 전 인증·프로젝트 소유권 검증이 필요하다.
