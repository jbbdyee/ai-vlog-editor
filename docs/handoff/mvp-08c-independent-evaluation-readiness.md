Manifest `cutory-v2-focused-eval-v0.1`은 버전 3, 상태 `PRE_REGISTERED_BEFORE_RECORDING`이며 3 Project·18 Scenario를 정의한다. 이는 촬영 의도이지 관찰 결과나 정답이 아니다. 읽기 전용 확인에서 `validate_focused_manifest.py`는 **PASS: 3 projects, 18 scenarios, 46 coverage cases**였다. `validate_focused_gt.py --mode draft`는 **PASS: 기존 8개 JSON의 구조 검사**였다. `--mode freeze-ready`는 **PENDING: 28개 미비 항목, 종료 코드 2**였다. 주요 미비 항목은 P2·P3의 source GT, P1의 일부 Memo/VLM GT, 세 Project의 Event GT다. Draft PASS나 freeze-ready 검사 자체는 사람의 GT 동결을 뜻하지 않는다.

현재 `.venv`의 Python 3.12.15와 로컬 PostgreSQL 읽기 전용 연결은 작동한다. 이 PowerShell 세션의 `PATH`에서는 `ffmpeg`, `ffprobe`, `docker` 실행 파일을 찾지 못했다. 따라서 새 영상을 처리하기 전에는 실행 경로와 실제 도구 동작을 다시 확인해야 한다. 이전 [07A 실제 영상 실행](mvp-07a-real-video-validation.md)의 환경 성공을 현재 세션의 가용성으로 간주하지 않는다. 저장 결과를 읽는 08B 실행기는 영상 디코딩이나 외부 Provider 호출이 필요하지 않다. 이번 조사에서는 원본 영상·프레임을 열거나 STT/FFmpeg를 재실행하지 않았다.

## 독립 주석 절차

1. **대상과 역할 분리:** P1-S01을 개발 세트로 분리한다. 새 평가자는 가능한 한 08A/08B 보고서·P1 GT 초안·촬영자 구간·D 후보·C 제안·예상 커버리지 수치를 보지 않은 상태에서 원본을 검토한다. 기존 초안을 작성하거나 08B 규칙을 본 사람의 주석은 독립성을 가진 새 GT로 세지 않는다. 평가자는 익명 source ID와 무작위 순서의 원본만 받고 시나리오 정답이 드러나는 파일명은 보지 않는다.
2. **영상 자체를 먼저 주석:** 두 평가자가 각각 원본 전체를 보며 실제 사건의 시작·끝, 사건 정체성, 의미 있는 반응·무관한 소음/화면 움직임, 독립 사건 사이 경계, 애매한 구간을 기록한다. 원본 시작 기준 초 단위이며 확실하지 않은 경계에는 불확실성과 근거를 남긴다. 한 사람이 이전 사건·메모 의도를 아는 경우를 별도로 표시한다. 자막/STT나 후보 출력으로 영상의 사건 경계를 역산하지 않는다.
3. **독립성·합의:** 평가자별 원본 주석과 작성 시각을 보존한다. 불일치는 제3자 또는 합의 검토로 해결하되 원래 판단을 지우지 않는다. 판단 불가·애매함을 강제로 하나의 사건으로 만들지 않는다. 기존 P1 초안·촬영자 노트는 **독립 주석 잠금 후** 차이를 확인하는 참고자료로만 연다. 개인정보를 포함한 원본·프레임·작업 중 로그는 Git 제외 로컬 공간에 둔다.
4. **출력 공개 순서:** 주석과 사례 분할·지표·실패 기준을 먼저 고정하고, 이후 D/C 결과를 평가자와 별도의 평가 담당자가 매칭한다. 입력 소스 SHA-256, 분석/승격 버전·설정 fingerprint, 후보 ID·Evidence 계보와 08B 실행기 커밋을 함께 남긴다. 원본 GT와 후보 ID 연결은 분리하고 기존 [Focused Dataset 지침](../../evaluation/datasets/cutory-v2-focused-eval-v0.1/ANNOTATION_GUIDE.md)을 따른다. 기존 GT를 결과에 맞춰 고치거나 새 GT를 이번 단계에서 생성·동결하지 않는다.

P1의 촬영자 노트와 초안은 이미 개발팀에 노출돼 있으므로 P1-S02~S06도 완전히 손대지 않은 외부 홀드아웃이라고 과장할 수 없다. 블라인드 **새 평가자**의 주석으로 누출을 줄일 수 있지만, 일반화 결론은 P2·P3와 추가 독립 부정 사례가 준비될 때까지 보류한다.

## D/C 비교 절차와 지표

평가 전 D는 현재 `build_promotion_manifest()`의 후보 교집합 결과, C는 커밋된 `evaluation/run_mvp08b_event_grouping.py`의 `group_candidates()`와 입력 검증으로 고정한다. 규칙, 테스트 기대값, 임계값을 P1~P3 정답에 맞춰 수정하지 않는다. 같은 소스·동일 Evidence 스냅샷에서 D 후보를 재생해 DB의 ID·구간·승격 근거와 대조한다. 재생이 불일치하면 **그 소스의 C 비교를 중단**한다. C는 원본 후보·Evidence를 쓰지 않는 읽기 전용 shadow 결과로 계산한다. 매체나 DB가 없으면 `NOT_RUN`으로 남긴다.

| 지표 | 정의와 보고 단위 | 주의점 |
| --- | --- | --- |
| 사건 커버리지 | 사람 주석 사건 구간과 D 후보 합집합 또는 C 제안 외피 합집합의 겹침 ÷ 사건 길이. 최고 단일 단위 coverage와 tIoU도 병기 | C 외피가 공백을 메운 효과를 별도 표시. 기존 Dataset B의 **coverage ≥0.70 및 tIoU ≥0.30** 판정은 바꾸지 않으며, 미동결 주석에 대한 정식 합격은 선언하지 않음 |
| 추가 포함 시간 | 각 표시 단위 외피에서 해당 사람 주석 사건과 겹치지 않는 초·비율; C 외피에서 원본 후보 합집합 밖의 초; 양성 Evidence가 전혀 없는 초; 두 근거의 교집합이 없는 초 | `4.84~5.54`처럼 전사는 있으나 교차 근거가 없는 시간을 “Evidence 전무”로 집계하지 않음 |
| 단위 수와 길이 | Source별 D 후보 수, C 제안 수, 전체 외피 길이, 길이 분포 | 단위 수 감소만으로 개선 판정하지 않음 |
| false split | 하나의 독립 주석 사건이 여러 D 후보 또는 여러 C 제안으로 분리됐는지; 사건별 연결 단위 수와 미포함 간격을 기록 | 복수 사건이 서로 가까운 경우와 구별; attribution이 애매하면 보류 |
| false merge | 하나의 C 제안이 서로 다른 사람 주석 사건에 속한 원본 후보를 묶거나 명시적인 must-not-merge 경계를 가로지르는지 | 단순 시간 근접·공통 장소·공통 단어만으로 같은 사건이라고 판단하지 않음. Event identity가 불명확하면 미판정 |
| 근거 추적성 | C의 모든 자식 후보 ID/구간·승격 쌍·SceneEvidence ID가 D/DB 스냅샷에 있고 값이 변하지 않았는지 | 누락·변형은 품질 수치와 무관하게 실행 실패 |

모든 수치는 Source별·사건별 원자료와 함께 집계하고 사건이 없는 음성/시각 활동 구간도 분모에서 숨기지 않는다. 음성 메모와 실제 사건을 합치는지, 조용하지만 중요한 행동을 놓치는지 따로 기록한다. 평가 계약의 cross-video `EventGroup` pairwise purity·`OVER_MERGE`/`OVER_SPLIT`와 이번 **같은 소스의 EventProposal** 지표를 합쳐 하나의 성능 점수로 만들지 않는다. 정량 허용치와 전체 합격 기준은 v2 계획대로 **TBD**이며, 독립 결과를 열기 전 평가 책임자가 사례 수·판정 경계·집계 규칙과 함께 사전 고정해야 한다. 다만 기준선 불일치, 원본 후보/Evidence 계보 손상, 확정된 별개 사건의 병합은 각각 실패로 기록한다. 검증 불능은 통과로 세지 않는다.

## 부정·경계 사례 계획

- **같은 소스의 복수 사건:** P1-S03 take02의 두 유사한 행동, P1-S06의 선물 열기와 뒤의 tapping/gesture는 기존 노트상 분리 필요성이 있다. 새 평가자가 먼저 독립적으로 확인한 뒤 C가 공유 전사/오디오에 의해 이를 합치는지 살핀다. 기존 노트의 시각을 C 규칙이나 주석 화면에 넣지 않는다.
- **무관한 신호:** P1-S04는 사전 등록된 떨어뜨림 요청과 일치하는 장면이 없다는 촬영자 기록이다. 이는 “영상 전체에 사건이 없다”는 뜻이 아니다. 향후 P2-S04의 반응과 무관한 소리, P2-S06의 사건 없는 pan·우발적 소리, P3-S05의 무의미한 촬영도 영상 확보 후 독립 판정한다.
- **긴/짧은 경계:** 지속 전사가 긴 오디오 공백을 가로지르는 사례, 붙어 있지만 다른 반응, 후보 중복·겹침, 밀리초 경계, 전사·오디오·영상 중 하나가 빠진 경우를 별도 실패 표에 기록한다. 현재 08B 합성 테스트는 결정성·불변성과 일부 차단을 확인했을 뿐 실제 의미 판정은 아니다.
- **영상 간 경계:** P1-S01↔S02의 비슷하지만 별개 촬영, P2의 도착↔별도 출발, P3의 유사한 별도 외출 준비는 기존 Manifest의 cross-video 사례다. C는 단일 Source만 받으므로 이 쌍을 **직접적인 C 병합 품질 사례로 사용하지 않는다**. 서로 다른 source 입력을 거부하는 안전성 확인과 향후 제품 `EventGroup` 평가를 분리한다.

## 현재 차단 요인과 다음 단계 체크리스트

- [ ] P2·P3 원본을 사전 등록된 Scenario와 연결해 로컬에 확보하고 파일명 추측 없이 SHA-256·길이·코덱·privacy 상태를 확인한다. P3-S03의 복사 관계는 실제 바이트로 확인한다.
- [ ] 현재 세션에서 FFmpeg/FFprobe 및 필요한 실행 경로를 확인한다. 격리된 프로젝트·출력 위치와 외부 LLM/VLM 호출 차단을 확인한 뒤 P1 추가 영상과 P2·P3의 STT·오디오·영상 분석, Evidence·D 후보를 생성한다. 기존 프로젝트·렌더·GT를 덮어쓰지 않는다.
- [ ] 새 평가자에게 D/C 결과·P1 촬영자 노트·GT 초안·예상 성과를 숨긴 원본 주석 패키지를 준비한다. 독립 주석과 불일치·모호성 기록을 먼저 잠근다.
- [ ] 평가 사례 목록, P1-S01 개발 사례 분리, false merge/false split attribution, 수치 허용치, 실패 기준을 결과 열람 전에 사전 등록한다. 부정·경계 사례의 충족 여부를 확인한다.
- [ ] 기존 GT 초안과 새 독립 주석을 원본 변경 없이 대조하고 필요한 인간 검토·동결 절차를 별도로 진행한다. `draft` PASS는 GT freeze가 아니다. 정식 focused 평가에서는 기존 Dataset B 판정과 Dataset D의 영상 간 Event 계약을 그대로 따른다.
- [ ] 위 준비를 확인한 후에만 독립 D/C 비교 실행 승인을 요청한다. 결과에는 성공·실패·미실행을 분리하고, P1-S01은 탐색/개발 사례로 따로 보고한다.

이번 MVP-08C에서 제품 코드·의존성, 08B 규칙·테스트 기대값, 평가 계약·GT·Manifest, 원본 영상·렌더 산출물은 수정하지 않았다. 외부 LLM/VLM API와 독립 영상 분석은 실행하지 않았으며 Git 커밋·Push도 하지 않았다.
