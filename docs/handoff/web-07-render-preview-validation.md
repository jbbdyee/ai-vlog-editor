# WEB-07 — 최종 렌더 결과 미리보기 검증

상태: **로컬 React 구현, 기존 QA MP4의 제한된 실제 Chrome 재생 검증 완료**. Windows `main`, 시작 HEAD `1a2d7d71c4c2bbdc8d01a917227cd176d7fc7843`. 기존 WEB-01~06/EVAL-01/02 미커밋 변경, 보호 대상 백엔드 테스트 3개, 원본·GT·Manifest·기존 렌더 결과를 보존했다. 제품 렌더 알고리즘·DB·인증 계약·의존성은 변경하지 않았다. 커밋·Push 없음. [WEB-04 실제 산출물 기록](web-04-react-e2e-validation.md)과 [WEB-06 원본 미리보기](web-06-source-preview-validation.md)를 참조한다.

## 기존 API 판단

새 미디어 API를 추가하지 않았다. 현재 프로세스의 `GET /projects/{id}/rendering`이 완료 결과와 해당 파일의 존재·경로·크기를 검증하고, 프로젝트/렌더 ID에 맞는 다운로드 URL 및 사용 가능 플래그를 제공한다. React의 기존 `downloadPath()`는 서버 URL이 예상 프로젝트·렌더 ID 경로와 정확히 같은지 다시 검사한다. `GET /projects/{id}/renders/{render_id}/download`와 `/subtitled/download`는 프로젝트·렌더 연결, 완료 상태, 파일 경로를 확인한다. 이는 사용자 인증·소유권 검증이 아니며 공개 배포를 허용하지 않는다.

기존 QA 완료 결과를 읽기 전용으로 시험한 실제 응답:

| 버전 | Content-Type | Content-Disposition | `Range: bytes=0-1023` | Chrome `<video>` |
| --- | --- | --- | --- | --- |
| 기본 MP4 | `video/mp4` | `inline` | `206`, 정확한 1024바이트·`Content-Range` | 메타데이터·재생·seek 성공 |
| 하드 자막 MP4 | `video/mp4` | `attachment` | `206`, 정확한 1024바이트·`Content-Range` | 이 Windows Chrome의 미디어 요소에서 메타데이터·재생·seek 성공 |

`attachment` 응답을 다른 브라우저까지 미디어 요소에서 재생한다고 일반화하지 않는다. 기존 다운로드 동작과 파일명은 유지했다. 잘못된 렌더 ID 422, 다른 프로젝트·없는 렌더 404, 없는 자막 파일 404 및 기본 MP4 유지, 없는 기본 파일 404, 범위 이탈 416은 별도 API 회귀에서 확인했다. 앱은 기본 MP4 파일 사용 가능 플래그가 없으면 플레이어를 보이지 않는다.

## React 구현

기존 편집·렌더 화면에 서버가 확인한 `COMPLETED` 결과만 보여 주는 `<video>` 플레이어를 추가했다. 사용자는 기본/한국어 하드 자막을 버튼으로 전환하고, 브라우저 기본 컨트롤로 재생·일시정지·탐색한다. 로딩·현재 시각·재생 오류를 표시한다. 자막 결과가 없으면 전환 버튼을 비활성화하고 기본 영상과 기존 다운로드를 남긴다. 파일이 상태 조회 후 사라져 미디어 요청에 실패해도 오류를 표시하고 다운로드는 별도로 재시도할 수 있다.

새 렌더 요청이 접수되거나 서버 상태가 `RUNNING`이면 이전 플레이어를 숨긴다. 새 완료 렌더는 프로젝트·렌더 ID·버전별 `key`로 미디어 요소를 새로 만들고 이전 시간/오류 상태를 버린다. 프로젝트 전환도 별도 Query key와 컴포넌트 key로 분리된다. 기존 계획과 마지막 완료 렌더가 다를 수 있다는 화면 안내는 유지한다. 서버 재시작 뒤 `NOT_STARTED`이면 남아 있는 파일을 결과로 표시하지 않는다.

## 실제 영상 검증과 한계

기존 WEB-04 격리 QA 프로젝트의 **이미 생성된** `final.mp4`, `final-subtitled.mp4`, `final.srt`를 읽기만 했다. 새 렌더·원본 업로드·분석은 실행하지 않았다. 두 MP4의 현재 SHA-256은 [WEB-04 기록](web-04-react-e2e-validation.md)과 각각 일치한다: 기본 `2d2150168971c9a8e633e68fd464f24d76833e661317cd49ec86a8cd4bae5c2d`, 자막 `3b720a6e77add537c8391a0483bec4fa14fb22f487a9be73cd59598fefc6a523`. 이번 FFprobe 재검사에서 둘 다 5.433333초, H.264 영상·AAC 오디오였다.

일반 API 프로세스는 서버 재시작 뒤 완료 기록을 잃으므로 기존 파일을 그대로 요청할 수 없다. **실제 파일을 제품 복구 기능처럼 표시하지 않기 위해**, `backend.tests.web07_preview_fixture_server`가 기존 QA 파일을 읽고 시험용 프로세스 메모리에만 해당 완료 결과를 등록하도록 했다. 이 도구는 렌더 파일·DB에 쓰지 않으며 운영 복구 구현이 아니다. 일반 제한 컨텍스트에서는 기존 하드 자막 파일 열기가 거부되어 API가 `206` 헤더 뒤 전송을 중단하는 환경 오류가 재현됐다. 권한이 있는 별도 로컬 읽기 컨텍스트에서 같은 파일의 해시와 실제 전송을 확인했다. 파일 권한을 변경하거나 소켓·Docker 권한을 확대하지 않았다.

시험용 완료 상태에서 실제 Chrome + Vite + FastAPI + PostgreSQL로 기본/자막 MP4 각각의 로드, 재생, seek, 디코딩 영상 프레임 증가를 확인했다. 자막 영상 약 2초 프레임의 **실제 한국어 문장 표시**를 화면에서 확인했다. 프레임 캡처는 Git에서 제외된 `web/test-results/`에만 남는다. 두 다운로드 버튼도 클릭하고 받은 바이트의 SHA-256을 각 API 응답과 비교했다. 전체 프레임·자막의 언어 품질이나 다른 브라우저·OS는 검증하지 않았다.

## 후속 작업

1. WEB-08에서 완료 렌더 메타데이터의 안전한 영속화·재검증·프로젝트/계획 연결과 재시작 후 누락·불완료 구분을 설계한다. 이번 시험용 메모리 등록을 제품 코드로 이전하지 않는다.
2. Chrome 이외 브라우저의 `attachment` 자막 응답 재생 가능성은 미검증이다. 실제 실패가 확인되면 기존 다운로드 계약을 지키면서 최소 읽기 전용 재생 응답을 검토한다.
3. 인증·사용자 소유권이 없는 로컬 API는 공개 배포하지 않는다. GT 미동결과 SceneCandidate 정량 품질 평가 미완료 상태를 유지한다.
