## 독립 주석 절차 초안

1. **사례 분리:** P1-S01은 개발 사례로 표시한다. P1-S02, S03 선택 take02, S04, S05, S06을 다음 독립 주석 후보로 둔다. 이는 주석·분석 준비 대상이라는 뜻이며 품질 평가 적합성의 판정은 아니다. P2·P3 미디어와 독립 주석은 아직 없다.
2. **블라인드 배포:** 조정자만 원본 파일과 위 해시·시나리오의 대응을 보관한다. 평가자에게는 원본 영상의 안전한 사본과 불투명한 사례 ID만 제공한다. 기존 GT 초안, 촬영자 기록, D/C 출력, 후보 시각·수·점수, 08B 기대 수치를 제공하지 않는다. 이미 이를 본 사람의 주석은 독립 주석으로 표기하지 않는다.
3. **기록 단위:** 영상의 첫 프레임을 0초로 삼고 각 사건의 `case_id`, `event_id`, `start_sec`, `end_sec`, 짧은 사건 설명, 관찰 근거, 확신도, 경계 불확실성, 주석자 ID·버전을 기록한다. `0 <= start_sec < end_sec <= duration_sec`를 확인한다. 시간은 플레이어가 허용하면 0.001초까지 기록하며 실제 판독 정밀도보다 높은 확실성을 주장하지 않는다. 사건이 없다면 빈 사건 목록과 그 사유를 남긴다.
4. **사건 경계:** 하나의 지속적인 행동·발화·반응·인과적 진행은 하나의 사건으로 표시한다. 별개의 행동 또는 명확한 시간·맥락 단절은 서로 다른 사건으로 나눈다. 같은 사물·장소·화자라는 이유만으로 합치지 않는다. 짧은 반응 장면도 독립적 의미가 있으면 보존한다. 음성·영상에서 판단이 엇갈리면 각각의 관찰 근거와 애매한 경계를 기록하고 억지로 확정하지 않는다.
5. **독립 판단과 합의:** 최소 두 평가자가 서로의 결과를 보지 않고 주석한다. 경계나 사건 수가 다르면 원본을 재검토해 차이를 기록하고, 필요하면 제3자가 조정한다. 최초 주석과 조정 이력을 모두 보존한다. GT 초안을 자동 복사하거나 기존 알고리즘 결과를 정답으로 승격하지 않는다.
6. **고정:** 주석 완료 후 출력 공개 **전에** 대상 파일 SHA-256, 주석 스키마·판본, 익명 사례 ID 대응표, 사건 정의, 평가 기준을 검토·고정한다. 수정은 버전을 올리고 이유를 남긴다. 기존 GT 초안이나 평가 계약은 덮어쓰지 않는다. 고정 전 결과는 탐색으로만 표시한다.

빈 주석 양식의 필드는 `case_id, annotator_id, annotation_version, media_sha256, event_id, start_sec, end_sec, description, observed_cues, confidence, boundary_uncertainty, ambiguous_reason`으로 둔다. 실제 사건 행은 주석자가 원본을 보고 작성한다. 이 문서는 빈 양식의 정의만 담고 있으며 주석 데이터나 새 GT를 생성하지 않았다.

고정 후 동일 입력에서 기존 D 후보와 변경하지 않은 C EventProposal을 계산한다. 사건별 커버리지, 전체·Evidence 지지 길이, 추가 포함 시간, 그룹 수, 원본 후보·Evidence 계보를 비교한다. **False merge**는 서로 다른 독립 주석 사건을 하나의 그룹이 연결하는 경우, **false split**은 한 사건이 필요 이상으로 여러 후보·그룹으로 끊기는 경우로 구분한다. 단순 겹침을 사건 일치로 인정할 최소 조건과 허용 경계 오차는 결과를 보기 전에 등록한다. 짧은 반응, 무관한 연속 사건, 긴 비지지 간격, 겹치거나 중복된 근거를 부정·경계 사례로 포함한다. P1-S01 수치는 탐색 사례로 별도 제시하고 독립 성능 향상 수치에 섞지 않는다. P1의 기존 초안·촬영 맥락이 이미 개발팀에 알려져 있으므로 블라인드 평가자라도 완전한 미사용 외부 데이터라고 주장하지 않는다.

## 격리 분석 계획과 차단 요인

- 새 영상 분석은 **별도 승인 후** S02 등 선택 대상별 새 프로젝트 ID를 만들고, 기존 프로젝트/소스/렌더 ID와 충돌하지 않는 저장·실험 출력 경로를 확인한 다음 한 건씩 수행한다. S03은 `take02`를 쓰며 보존용 `take01`을 대체하거나 이름을 바꾸지 않는다. 원본은 읽기 전용으로 취급하고 분석 전후 해시를 재확인한다.
- 실행 전 DB 백업·저장 경로, 출력 충돌 방지, 가용 공간, 로컬 STT 모델 캐시, FFmpeg/FFprobe의 프로세스 `PATH`, PostgreSQL 쓰기 연결, Docker 엔진을 다시 점검한다. 외부 LLM/VLM 호출 경로를 배제하고 모델 다운로드도 의도치 않게 발생하지 않도록 오프라인 설정을 확인한다. 비용·처리 시간은 사전 측정 없이는 확정할 수 없다.
- 주석자는 원본 접근 권한과 개인정보 취급 방법이 준비되어야 한다. 원본·프레임·음성·주석자의 개인식별 정보·비밀키는 Git에 추가하지 않는다. 사본·임시 분석 결과는 기존 산출물과 분리된 비공개 위치를 사용한다.
- **현재 차단:** 독립 주석과 그 고정이 미완료다. S02~S06의 저장 분석 결과가 없고, 분리된 DB/출력 경로의 실제 쓰기 실행을 검증하지 않았다. P2·P3 실제 미디어·주석·분석 결과도 없어 일반화 평가는 불가하다. GT freeze-ready는 [08C](mvp-08c-independent-evaluation-readiness.md) 기준 `PENDING`이며 미비 항목 28개다.
- **다음 단계 진입 조건:** 블라인드 주석자·비공개 전달 경로 확보, 사건 정의와 경계 기준 사전 등록, 선택 미디어 해시 확인, 주석 고정, 격리 저장·DB·모델 캐시·도구 경로 확인, 한 건씩 신규 분석하는 별도 승인. 그 뒤에야 변경하지 않은 D/C를 비교한다. GT 미동결 상태의 결과는 탐색 분석으로 표기하며 자동 추천 품질 합격 또는 제품 반영 근거로 단정하지 않는다.
