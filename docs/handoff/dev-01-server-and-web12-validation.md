# DEV-01 — 개발 서버 상태와 WEB-12 실제 데이터 검증

상태: **기존 서비스를 재시작하지 않고 정상 상태 확인, WEB-12 실제 FastAPI·PostgreSQL·Chrome 읽기 전용 검증 완료.** 새 렌더·DB 쓰기·마이그레이션·설정 변경·커밋·Push는 실행하지 않았다.

## 서버 상태와 이전 미응답 원인

- 작업 시작 시 Git은 main, HEAD 1a2d7d71c4c2bbdc8d01a917227cd176d7fc7843. 기존 미커밋 파일과 보호 대상 백엔드 테스트 3개의 변경량(6/1, 6/1, 1/1)을 보존했다.
- 제한된 셸에서는 프로세스·포트 조회가 접근 거부되고 FastAPI 직접 요청도 응답하지 않았다. 읽기 권한이 허용된 점검에서는 기존 FastAPI 프로세스가 127.0.0.1:8000에서 수신했고 직접 OpenAPI 200, Vite 127.0.0.1:5173 200, Vite의 /api 프록시 OpenAPI 200, Tailscale HTTPS 443 200이었다. 따라서 앞선 미응답은 이 셸의 접근 제한으로 판단하며 서버 종료나 애플리케이션 오류의 증거는 없었다. 서버 로그의 과거 오류까지 확인한 것은 아니다.
- Docker Desktop의 PostgreSQL 컨테이너는 healthy, IPv4 게시 주소는 127.0.0.1:5432만 표시됐다. 기존 DB에 SELECT만 수행해 연결 성공, Alembic revision b8c01e2a4f60, 프로젝트 12개, 영속 렌더 기록 0개를 확인했다. Tailscale Serve는 HTTPS 443→Vite 5173, TCP 11434·2222의 기존 목적지를 유지했다.
- FastAPI·Vite·PostgreSQL·Tailscale을 중단하거나 재시작하지 않았다. 컨테이너·볼륨·설정도 변경하지 않았다.

## 실제 WEB-12 읽기 전용 검증

기존 4장면 저장 계획이 있는 프로젝트를 사용했다. 실제 GET EditPlan은 후보 ID 4개, 무효 ID 0개였고 GET SceneCandidate는 후보 17개, GET 처리 상태는 원본 2개, GET 렌더 기록은 0건이었다. 원본 영상 파일과 DB를 수정하지 않았다.

| 저장 순서 | 원본 | 시작–종료 | 구간 길이 |
| --- | --- | --- | --- |
| 1 | P1-S01 | 2.44–2.62초 | 0.18초 |
| 2 | P1-S01 | 8.86–11.00초 | 2.14초 |
| 3 | P1-S02 | 4.60–5.20초 | 0.60초 |
| 4 | P1-S02 | 30.68–33.92초 | 3.24초 |

API 값의 구간 길이 합은 **6.16초**다. 실제 Chrome에서 375px와 1440px 모두 저장 순서, 파일명, 개별 시간·길이, 장면 수 4개와 예상 길이 6.16초가 표시됐다. 각 너비의 문서 scrollWidth는 clientWidth와 같았고 검토 영역은 뷰포트 안에 있었다. 기존 장면을 화면에서 임시로 추가하자 초안과 서버 저장 계획이 달라져 렌더 버튼이 비활성화됐고 검토 안내가 표시됐다. 새로고침 뒤 서버의 4장면 계획으로 복구됐다. 브라우저의 프로젝트 API 쓰기 요청은 **0건**이었다.

기존 렌더 기록이 0건이어서 이전 렌더가 있는 실제 DB 화면에서의 분리 표시는 미검증이다. 현재 화면의 기록 없음 안내와 WEB-12의 이전 산출물 구분 문구는 확인했다. 저장 중·저장 실패, 빈 계획, 과거 렌더가 있는 사례는 기존 단위/Mock Chrome 검증 범위다. 실제 렌더, MP4 결과 길이, 실제 iPhone Safari, 다른 tailnet 기기 접근은 이번에 검증하지 않았다.

TypeScript 검사와 Vite 프로덕션 빌드가 통과했다. 검증용 브라우저 스크립트와 결과는 Git 제외 테스트 출력 경로에 두었다.
