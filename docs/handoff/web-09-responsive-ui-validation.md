# WEB-09 — 모바일 반응형 UI 검증

상태: React UI 구현·모의 API Chrome 레이아웃 검증 완료. **변경 후 실제 iPhone Safari 검증은 미실행**. 시작 브랜치 `main`, HEAD `1a2d7d71c4c2bbdc8d01a917227cd176d7fc7843`. 기존 WEB-01~08B·EVAL 미커밋 변경과 보호 대상 백엔드 테스트 3개를 보존했으며 커밋·Push는 하지 않았다.

## 관찰과 수정

사용자가 iPhone의 Tailscale 접속에서 프로젝트 제목·ID 잘림, 가로 스크롤, 큰 글자·여백과 긴 페이지 탐색을 보고했다. 코드에서 프로젝트 헤더의 줄바꿈 없는 flex 자식, 소스 ID·긴 파일명, 선택 장면 행의 조작 버튼에 밀리는 텍스트, 모바일에서도 큰 제목과 카드 여백을 확인했다. 이번 변경 전 실제 iPhone 화면의 치수·스크린샷은 확보하지 못했으므로 브라우저 에뮬레이션을 실제 기기 재현으로 표현하지 않는다.

- 공통 레이아웃·카드의 모바일 가로 패딩과 상하 간격을 줄이고 `min-w-0`을 지정했다. 홈·프로젝트 제목의 모바일 크기를 낮추되 데스크톱 크기와 두 열 구조를 유지했다.
- 프로젝트 제목은 긴 단어도 줄바꿈하고 UUID·파일명·진단 ID·오류 문구도 해당 카드 안에서 줄바꿈한다. `overflow-x: hidden`으로 넘침을 감추지 않았다.
- 기존 다섯 작업 단계를 버튼처럼 읽히는 앵커 링크로 바꾸고, 모바일에서는 스크롤 중 상단에 유지한다. 등록·처리·분석·편집/렌더 섹션의 실제 ID로 이동하며 sticky 바에 가리지 않도록 scroll margin을 지정했다. 후보 미리보기의 원본 플레이어 이동도 유지했다.
- 선택한 장면은 모바일에서 파일명/시각과 미리보기·순서 버튼을 별도 줄로 배치했다. 주요 실행은 기존 cyan 버튼, 상태 재조회 등 보조 동작은 기존 secondary 스타일을 유지한다.
- 원본·최종 영상 플레이어는 `w-full`, `min-w-0`, `playsInline`과 브라우저 기본 컨트롤을 유지한다. 모바일 자동 재생 거부 시 기존 안내와 수동 재생 동작을 사용하며 MOV/HEVC 지원을 보장하지 않는다.

## 실행 검증

| 검증 | 결과 |
| --- | --- |
| React 단위 | Vitest **33 통과, 실패 0**. JSDOM 미디어 메서드 미구현 로그는 실제 영상 재생 검증이 아니다 |
| 타입·빌드 | `tsc -b` 및 Vite production build 통과 |
| 모의 API Chrome | 기존 WEB-01~04 경로 7건과 WEB-09 5건, **총 12 통과**. 생성·조회·업로드·처리·후보 선택·계획 저장·렌더/다운로드 오류 회귀를 포함 |
| 뷰포트 | 320·375·390·430px 및 1440px의 홈·전체 프로젝트 화면에서 `documentElement.scrollWidth <= clientWidth`, 실제 요소 경계, 단계 링크 이동·모바일 sticky 위치·두 플레이어 너비 확인. 영상 응답은 Mock이며 재생 품질 검증이 아니다 |
| 시각 검토 | Git 제외 `web/test-results/`의 320px·1440px 전체 화면 캡처를 확인. 320px 선택 장면에서 텍스트가 세로로 눌리는 문제를 발견해 텍스트/버튼 행을 분리한 뒤 재검사 |

실제 iPhone Safari, 맥북 Safari, Tailscale 경유 터치·키보드·미디어 재생은 이번 작업에서 실행하지 않았다. 실제 기기에서는 320px급 화면과 현재 iPhone 너비에서 제목/ID, 단계 이동, 파일 선택, 후보 미리보기와 두 렌더 플레이어의 재생·탐색을 다시 확인해야 한다. Safari의 자동 재생 정책과 HEVC 지원은 Chrome 에뮬레이션으로 판정할 수 없다.

백엔드 API·PostgreSQL 스키마·원본/렌더 파일·GT·Manifest·Tailscale Serve 설정은 변경하지 않았다. 실행 중인 FastAPI·PostgreSQL은 재시작하지 않았다.
