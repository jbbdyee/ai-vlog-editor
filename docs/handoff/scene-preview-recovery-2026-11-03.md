# 실제 MOV 소스 처리 및 장면 분석 복구 — 2026-11-03

## 관찰과 복구

로컬 프로젝트 `d2cb6a3b-ed3c-4a7f-b067-c386870016e2`의 등록된 MOV 한 건은 `PROBE_FAILED`였고 후속 오디오 추출·STT는 실행 전이었다. 원본은 178,504,175바이트이고 업로드 때 기록한 SHA-256과 현재 해시가 일치했다. 번들 FFprobe 9.0.2로 읽으면 246.500001초, H.264 영상과 AAC 오디오가 확인됐다. 당시 API의 원시 예외 로그는 남지 않았으나, 현재 셸에서 코드의 `probe_media`를 재실행하면 `ffprobe` 실행 파일을 찾지 못하는 오류가 재현됐다.

다른 프로젝트의 활성 처리·분석·렌더 작업 0개를 확인하고 FastAPI만 번들 FFmpeg/FFprobe 경로를 프로세스 `PATH`에 넣어 재시작했다. DB 영속 렌더 플래그는 유지하고 Vite·PostgreSQL·Tailscale Serve는 재시작하거나 설정을 바꾸지 않았다. `retry_source_stage(PROBE)`를 이 소스에만 명시적으로 실행한 결과 PROBE, 오디오 추출, STT, 메모 감지가 완료됐고 전사가 저장됐다. 이어 기존 프로젝트 처리 API로 상위 상태를 `COMPLETED`로 갱신했다. 외부 LLM/VLM 키는 해당 실행 프로세스에서 비우고 로컬 STT를 오프라인으로 실행했다.

## 장면 분석의 두 번째 오류

첫 장면 분석은 `SCENE_DISCOVERY_FAILED`였다. 원인을 같은 소스에서 재현했을 때 전사 근거 45개의 압축 매니페스트가 1,397자로, `scene_analysis_work_items.result_reference`의 1,024자 한계를 넘었다. 오디오 1개와 영상 19개 근거의 기존 인코딩은 각각 345자와 841자였다. DB 스키마나 후보 생성 규칙을 바꾸지 않고, 기존 `zlib:` 읽기를 유지하면서 반복 메타데이터를 공유하는 `zlib2:` 저장·복원을 추가했다. 실제 전사 45개의 결과는 1,014자로 저장·복원했으며 내용이 일치했다. 별도 합성 회귀 테스트 4건은 표준 `unittest`에서 통과했다. 기존 전체 pytest는 현재 `.venv`에 pytest가 없어 실행하지 못했다.

수정된 FastAPI만 다시 시작해 장면 분석을 실행한 결과 `COMPLETED`, 소스 결과 `ABSTAINED`, 후보 **0개**였다. 저장된 진단은 `UNSUPPORTED_COMBINATION`이며 전사 근거 45개, 영상 활동 11개, 품질 관련 9개, 오디오 활동 0개다. 이는 오류 복구와 별개로 현재 Evidence 교집합 규칙이 이 영상에서 후보를 만들지 않았다는 뜻이다. 후보 생성 규칙·임계값을 이 영상에 맞춰 조정하지 않았고, 편집 계획·렌더·SRT·하드 자막 MP4도 생성하지 않았다.

현재 React의 `처리 다시 요청`은 프로젝트 처리 API를 호출하지만, 그 API는 `FAILED` 소스를 재시도 대상에서 제외한다. 따라서 해당 버튼은 이번 실패를 복구하지 못했다. 별도 UI/API 개선이 필요하다. 새 후보와 자막 영상 시연을 위해서는 근거 조합이 확인된 다른 영상 또는 사건 선택을 위한 별도 설계가 필요하다. 사용자 승인 없는 임의 후보나 평가 정답은 생성하지 않는다.

이번 작업에서 원본·GT·Manifest·기존 렌더 파일은 수정하지 않았다. Git 커밋·Push는 하지 않았다.

## 후보 0개의 추가 원인 분석

같은 MOV에서 오디오를 임시 PCM16 WAV로 추출해 현재 `analyze_audio_wav`의 20ms RMS 계산을 읽기 전용으로 재현했다. 12,325프레임의 조용한 절반 중앙값은 −21.612 dBFS였고, 현재 `energy_margin_db=10`을 더한 활동 기준은 −11.612 dBFS였다. 실제 최대 프레임은 −11.627 dBFS로 기준보다 약 0.015 dB 낮아 활동 프레임·활동 구간이 모두 0개가 됐다. 그 결과 전체를 `LONG_SILENCE`로 취급한다. 저장된 전사 근거 45개와 서로 맞지 않는 진단이지만, 전사 자체의 정확도나 각 후보의 품질을 검증한 것은 아니다.

독립 비교용 P1-S01의 같은 계산에서는 조용한 절반 중앙값 −64.902 dBFS, 기준 −54.902 dBFS, 활동 프레임 234/675개 및 활동 구간 10개였다. 이 비교는 현재 기준이 신호의 레벨 분포에 크게 의존한다는 근거이며, 특정 대체 임계값의 안전성을 입증하지는 않는다. 해당 246.5초 영상에서 기준을 임의로 −15 dBFS로 낮춘 읽기 전용 예시에서는 활동 구간이 113개로 늘어 과잉 분할 위험이 보였다. 제품 임계값·후보 생성 규칙·평가 계약은 변경하지 않았다.

`build_promotion_manifest`의 세 규칙 모두 `AUDIO_ACTIVITY`와 다른 근거의 시간 교집합을 요구한다. 따라서 이 영상의 전사 45개와 영상 활동 11개만으로는 후보를 만들 수 없으며, 0개 결과는 현재 코드의 규칙대로다. 안전한 개선은 음량 압축·지속 배경음·진짜 무음 사례를 분리한 오프라인 검증과, 여러 영상에서 후보 수·false positive·구간 길이를 비교한 뒤 결정해야 한다. 현재 영상에 맞춘 기준값 조정이나 임의 후보 삽입은 하지 않았다. 현재 프로젝트의 편집 계획·MP4·SRT·하드 자막 MP4는 여전히 미생성 상태다.
