# WEB-01B — React·FastAPI·PostgreSQL 실제 브라우저 통합 검증

## 기준과 실행 환경

- 실행 시점: 2026-10-26, Windows, `main` HEAD `1a2d7d71c4c2bbdc8d01a917227cd176d7fc7843`. WEB-01은 미커밋 상태다.
- 기존 미커밋 백엔드 테스트 파일 3개와 `mvp-07b-multi-clip-validation.md`를 보존했다. 원본 영상·GT·Manifest·기존 프로젝트·렌더 산출물은 수정하거나 삭제하지 않았다.
- 기존 PostgreSQL 17.11 연결을 재사용했다. DB 초기화·마이그레이션·Docker 이미지 다운로드는 하지 않았다. Docker CLI 상태는 이번 실행에서 재검증하지 않았으며 DB가 이미 응답해 Docker 조작은 필요하지 않았다.
- 새 FastAPI 서버를 `127.0.0.1:8000`, Vite를 `127.0.0.1:5173`에 일시 실행했다. Vite의 `/api` 프록시는 실제 FastAPI로 연결했다. 두 서버는 검증 후 종료했다. 외부 공개 배포는 하지 않았다.
- Python 3.12.15, faster-whisper 1.2.1, PyAV 18.1.0. 로컬 `small` STT 모델을 `local_files_only=True`로 사전 확인했다. 실행 프로세스에만 번들 FFmpeg 9.0.2 경로와 `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`을 설정하고 외부 LLM/VLM 키는 빈 값으로 지정했다. `.env`는 변경하지 않았다. 이 소스 처리 경로에서 외부 LLM/VLM은 호출하지 않았다.
- 실제 입력은 `evaluation/data/P1/P1_S01_take01.MOV` 한 건이다. 141,327,567바이트, SHA-256 `205e4143822520183d446c154fc314f607b3c948ec2e264b37195933d89a01d2`; 기존 [MVP-07A](mvp-07a-real-video-validation.md) 기록과 일치한다. P1-S01은 재사용한 개발 사례이며 품질 평가의 새 독립 표본이 아니다.

## 브라우저 및 API 결과

Playwright가 로컬 Chrome을 실제로 조작했다. 주 경로에는 API 모의 응답을 쓰지 않았다. 재현 테스트는 `web/e2e-real/web01b.spec.ts`이며 전용 서버가 실행 중일 때 `cd web; pnpm test:e2e:real`로 실행한다. 실패 경로는 코드에 명시된 환경변수와 테스트 이름으로 개별 실행한다. 테스트를 다시 실행하면 새로운 QA 프로젝트와 원본 사본이 추가되므로 임의로 반복하지 않는다.

| 단계 | 결과 | 확인 근거 |
| --- | --- | --- |
| React 접속·존재하지 않는 ID | 통과 | 첫 화면 표시, 미존재 UUID는 실제 API 404·`PROJECT_NOT_FOUND` 표시 |
| 프로젝트 생성 | 통과 | 실제 `POST /projects` 201, URL에 서버 발급 ID 반영 |
| 잘못된 파일 형식 | 통과 | `.txt`는 브라우저에서 거부; 형식만 MP4인 잘못된 바이트는 실제 API 415·`INVALID_SOURCE_MEDIA` 표시 |
| P1-S01 업로드 | 통과 | 실제 `POST /sources` 201, 서버 소스 ID와 파일명 표시; API·DB 재조회 확인 |
| 소스 처리 접수 | 통과 | 실제 `POST /process` 202·`accepted=true`; 이를 완료로 간주하지 않음 |
| 중복 처리 요청 | 통과 | 같은 프로세스의 활성 작업 중 두 번째 실제 요청 409 |
| 상태 조회·완료 | 통과 | 실제 `GET /processing`을 따라 `COMPLETED`, 완료 1·실패 0·차단 0 확인 |
| 새로고침·ID 재접속 | 통과 | 두 경우 모두 서버 상태 `COMPLETED` 재조회 |
| 업로드 취소 | 통과(제한) | 별도 QA 프로젝트에서 전송 속도를 제한한 실제 요청을 브라우저에서 취소; 취소 안내 표시, 전후 DB 소스 수 1→1. 취소 시점 이후 서버의 임시 업로드 파일 수명은 검사하지 않음 |
| 백엔드 연결 실패 | 통과 | 이번에 시작한 FastAPI만 중지한 뒤 Vite 프록시 오류를 브라우저에 표시; 프로젝트 생성 성공으로 처리하지 않음 |

첫 실행에서는 프로젝트 `373f4ec4-6bdb-4405-83fc-166d487bf3ba`에 원본이 등록된 후 Playwright 선택자가 동일한 소스 ID를 알림과 목록 양쪽에서 찾아 strict mode 오류로 중단됐다. 제품 오류가 아니며 선택자를 정확 일치로 고쳤다. 해당 격리 QA 프로젝트와 등록 소스는 보존했고 업로드 취소·415 검증에 재사용했다. 이후 두 번째 격리 프로젝트 `c6782332-b2bf-4e48-956a-33bc127670fc`에서 주 경로가 끝까지 통과했다. QA 데이터는 삭제하지 않았다.

## 서버·DB 교차 확인

읽기 전용 트랜잭션으로 두 번째 프로젝트를 조회했다. 프로젝트 상태는 `COMPLETED`, 소스 `042f8705-4d15-4b70-92e6-c2e8d83c4b11`도 `COMPLETED`다. 저장된 source fingerprint와 격리 저장된 원본 사본의 141,327,567바이트·SHA-256은 입력과 동일하다. 저장된 미디어 정보는 길이 13.498초, HEVC 영상·AAC 오디오다. `PROBE`, `AUDIO_EXTRACTION`, `STT`, `MEMO_DETECTION` 네 단계가 모두 `COMPLETED`, 오류 코드는 없고 각 시도 횟수는 1이다. 전사 행 1건을 확인했다. 이는 WEB-01 소스 처리 완료의 근거이며 SceneCandidate 생성, 편집, 렌더링 또는 영상 품질 합격의 근거는 아니다.

## 발견한 결함과 변경

실제 백엔드 중단 시 Vite 프록시가 본문 없는 5xx를 반환했고 WEB-01 화면은 이를 “서버 응답을 읽을 수 없습니다”로 표시했다. `web/src/api/projects.ts`에서 **본문을 읽을 수 없는 5xx에 한해** “서버에 연결할 수 없습니다”로 바꾸고 `web/src/test/web01.test.tsx`에 회귀 테스트 1건을 추가했다. 백엔드 계약이나 처리 파이프라인은 변경하지 않았다.

## 테스트 범위와 남은 위험

- 수정 후 `pnpm test`: 10건 통과. `pnpm build`: TypeScript 검사·프로덕션 빌드 통과.
- 기존 모의 API Chrome E2E: 2건 통과. 실제 API Chrome E2E: 주 경로 1건, 415·취소 1건, 백엔드 중단 1건을 각각 실행해 통과했다. 중단 검사 실행 전 동일 테스트의 문구 기대가 실패했고, 위 수정 후 재실행해 통과했다. 환경변수로 선택되지 않은 테스트는 스킵이며 통과에 더하지 않는다.
- 실제 소스 처리 완료는 API와 DB로 확인했다. 화면 밖의 STT 전사 정확도, SceneCandidate·EditPlan, 렌더링, 영상 시청 품질, 다른 영상·브라우저·운영체제, 장시간·대량 업로드는 이번 범위에서 확인하지 않았다.
- 처리 요청의 409 실패 응답과 잘못된 미디어의 415는 확인했지만 STT 또는 다른 단계가 실제로 실패하는 소스 처리 작업은 의도적으로 만들지 않았다. 그런 경우의 브라우저 표시는 미검증이다.
- 현재 API에는 인증과 프로젝트 소유권 검증이 없다. 로컬 개발 범위만 유지한다. 취소 직후 서버가 등록을 마친 경합이나 네트워크가 느린 대용량 업로드는 추가 검증이 필요하다.

WEB-01의 프로젝트 생성·등록·소스 처리 화면은 실제 백엔드와 연결해 확인됐으므로 WEB-02의 다음 화면 연결을 시작할 수 있다. WEB-02에서도 해당 API의 실제 브라우저 검증을 별도로 수행해야 하며, 공개 배포 준비가 완료됐다는 뜻은 아니다.
