# WEB-12 — 렌더 전 편집 계획 검토 UX

상태: **React 구현, 단위·Mock Chrome 검증 완료. 기존 FastAPI·PostgreSQL 읽기 전용 화면 검증은 미실행. 실제 영상 렌더 미실행.**

## 기존 계약과 변경

- 기존 GET/PUT scene-edit-plan API는 순서가 있는 후보 ID 목록을 저장한다. scene-candidates API의 소스 ID·시작·종료 시각과 소스 처리 응답의 원본 파일명을 사용한다. 백엔드 API, DB, 렌더 알고리즘은 변경하지 않았다.
- 별도 화면을 만들지 않고 렌더 카드의 실행 버튼 위에 검토 영역을 배치했다. 서버에서 조회한 **저장된** 후보 ID 순서로 소스명, 시작·종료, 각 길이, 장면 수와 합산 예상 길이를 표시한다. 파일명을 조회하지 못하면 소스 ID를 표시한다.
- 예상 길이는 각 후보의 종료 시각에서 시작 시각을 뺀 값을 합산한다. 화면에는 소수 둘째 자리까지 표시한다. 이는 편집 계획 기준 추정치이며 실제 MP4 길이와 정확히 일치하거나 렌더 전 영상 재생 미리보기임을 뜻하지 않는다.
- 저장 전 변경, 저장 중, 저장 실패, 초안과 서버 계획 순서 불일치, 빈 계획, 무효 후보 또는 잘못된 시간 구간에서는 검토 목록과 렌더 실행을 차단하고 이유를 안내한다. 저장 완료 후 서버 응답을 반영한 계획만 검토한다. 기존 렌더 기록은 현재 계획의 예상 결과와 분리해 표시한다. 수정 링크는 기존 장면 선택 카드로 이동한다.

## 검증

| 수준 | 결과 |
| --- | --- |
| React 단위 | 전체 Vitest **44건 통과, 실패 0**. WEB-12 전용 4건에서 저장 순서·소스명·개별 길이·합계, 미저장/저장 중/저장 실패 차단, 재시도 후 서버 순서 표시, 빈 계획과 이전 렌더 기록의 분리를 검증했다. |
| Mock Chrome | WEB-11/12 관련 **10건**과 WEB-03 편집·렌더 회귀 **2건**, 합계 **12건 통과, 실패 0**. WEB-12는 320·375·390·430·1440px에서 검토 영역 경계와 문서 가로 넘침, 저장 순서, 수정 링크를 확인했다. WEB-12 테스트의 렌더 POST는 0건이다. WEB-03의 렌더 요청은 Mock 응답만 사용했다. Mock 응답은 실제 DB·영상 검증이 아니다. |
| 정적 검사 | TypeScript 프로젝트 검사와 Vite 프로덕션 빌드 통과. |
| 실제 환경 | Vite localhost:5173 HTTP 200 확인. 이 실행 환경에서는 FastAPI localhost:8000과 OS 포트 조회에 접근하지 못해 기존 DB 계획의 실제 Chrome 읽기 전용 검토는 수행하지 못했다. |

실제 영상 렌더, MP4 길이와 예상치 대조, 실제 iPhone Safari 조작은 미검증이다. 원본 영상·GT·Manifest·기존 렌더 파일과 DB에는 쓰지 않았고 커밋·Push하지 않았다.
