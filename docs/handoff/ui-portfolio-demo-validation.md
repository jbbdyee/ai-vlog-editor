# 포트폴리오 시연 UI 점검

## 범위와 변경 이유

React `web/`은 프로젝트 생성·영상 등록·소스 처리·장면 분석·후보 선택·계획 저장·렌더링·두 MP4 조회를 기존 FastAPI로 수행한다. 이번에는 API, 백엔드, 데이터 모델을 변경하지 않았다. 좁은 화면에서 단계 메뉴와 긴 서버 상태·버튼 문구가 카드 경계를 밀 수 있어 레이아웃만 보완했다.

- 320px에서는 단계 메뉴 2열, 390px 이상 3열, 640px 이상 5열로 배치한다. 스크롤 위치와 단계 링크는 유지한다.
- 공통 버튼은 긴 문구를 줄바꿈하고, 프로젝트 상태·분석 진단·렌더 상태는 카드 안에서 줄바꿈한다. `overflow-x: hidden`으로 넘침을 숨기지 않았다.
- 업로드·소스 처리·장면 분석의 모바일 아이콘·간격을 맞췄다. 장면 후보와 Evidence 진단의 건수는 서버 응답 배열의 실제 길이로 표시한다. 렌더 기록은 조회 중·빈 기록·오류를 구분한다.
- 후보는 관측 결과이며 품질 순위로 표현하지 않는다. 렌더 전 예상 길이는 저장된 구간 합계이며 재생 결과의 정확한 길이를 뜻하지 않는다.

## 실행 및 검증

README의 로컬 FastAPI·PostgreSQL 실행 방법을 따른 뒤 `cd web`, `pnpm install --frozen-lockfile`, `pnpm dev`로 화면을 연다. Vite의 `/api` 프록시는 기본적으로 `127.0.0.1:8000`을 사용한다. 인증이 없어 공개 배포용은 아니다.

2026-11-02 Windows checkout에서 React 단위 테스트 45건 통과, TypeScript `tsc -b`와 Vite 프로덕션 빌드 통과. 모의 API Chrome Playwright 30건 통과. 300·320·375·390·430·1440px에서 홈·프로젝트의 문서 너비와 주요 요소 경계, 단계 링크, 영상 플레이어 폭을 확인했다. 모의 API로 프로젝트 생성·업로드·처리, 분석·후보, 계획 저장·순서, 렌더·다운로드와 오류 화면을 회귀 확인했다.

이번 점검은 실제 영상 처리·렌더링 또는 품질 평가를 실행하지 않았다. 실제 iPhone Safari 조작과 이번 변경을 적용한 실제 FastAPI·PostgreSQL 화면 검증은 남아 있다. 과거 실제 통합 검증 범위는 WEB-04, WEB-06, WEB-07, DEV-01 기록을 따른다.
