# WEB-11 — 장면 선택 및 편집 순서 UX

상태: **React 구현·Mock Chrome·격리 PostgreSQL 실제 API 저장/재조회 검증 완료. 현재 사용 중인 DB는 읽기 전용 확인, 실제 영상 렌더 미실행.** 시작 Git은 `main`, HEAD `1a2d7d71c4c2bbdc8d01a917227cd176d7fc7843`이며 기존 미커밋 변경 및 보호 대상 백엔드 테스트 3개를 보존했다. 커밋·Push하지 않았다.

## 확인한 기존 계약과 공백

- `web/src/features/scenes/scene-analysis.tsx`는 후보 구간·Evidence와 미리보기를 제공한다. 후보는 품질 순위가 아니다. `web/src/features/edit/edit-render.tsx`에는 이미 후보 선택·해제, 선택 목록, 위·아래 순서 변경, 저장과 재조회가 있었다. `ProjectPage`는 프로젝트 ID를 key로 주어 화면 상태를 분리한다.
- `GET/PUT /projects/{id}/scene-edit-plan`의 본문은 **순서 있는 `candidate_ids` 목록**이다. 백엔드 `save_scene_edit_plan`은 중복·무효 후보를 거부하고 빈 목록도 저장할 수 있다. UI만 빈 선택 상태의 저장을 막고 있었다. 서버 순서가 요청과 다르게 돌아와도 이전 UI는 성공으로 표시할 수 있었다.
- WEB-06 원본/후보 플레이어, WEB-08C 영속 렌더 기록, WEB-10 목록 및 WEB-09B 모바일 경계를 그대로 재사용한다. 기존 후보 생성·렌더 API·DB 모델은 변경하지 않았다.

## 변경

- 후보 목록에 선택 표시와 선택 여부 버튼 상태(`aria-pressed`), 선택한 장면 수를 추가했다. 선택 목록에서도 해제할 수 있고, 해제와 이동은 같은 초안 배열을 갱신한다.
- 위·아래 버튼은 모바일에서 최소 44×44px로 두고 첫 장면의 위, 마지막 장면의 아래 이동은 기존처럼 비활성화한다. 이동 즉시 화면 순서와 저장되지 않은 변경 표시가 바뀐다. 드래그 앤 드롭이나 타임라인 편집은 추가하지 않았다.
- 빈 계획 저장을 허용하되 빈 계획의 렌더 버튼은 계속 비활성화한다. 저장 중·저장 완료·저장 실패를 구분한다. `saveEditPlan`은 응답의 후보 ID 순서가 요청과 정확히 같고 무효 ID가 없을 때만 성공으로 인정한다. 실패·불일치 시 초안 순서를 보존하고 재시도할 수 있다. 저장 성공 후 서버 응답을 Query 캐시에 반영하고 계획을 재조회한다.
- 후보 길이와 소스 파일명은 기존 API/처리 응답에 있는 값만 보여 준다. 추천 점수는 백엔드에 없어 표시하지 않는다.

## 남은 범위

실제 iPhone Safari의 터치 조작과 현재 사용 중인 DB에 대한 새 프로젝트 쓰기 E2E는 수행하지 않았다. 실제 영상 렌더·두 MP4 결과 품질도 이번 범위가 아니다. 동시 편집자가 있을 때 계획 충돌 알림은 현재 API에 버전 조건이 없어 별도 설계가 필요하다. SceneCandidate 추천 점수/순위는 여전히 없으며 품질 평가를 했다고 해석하면 안 된다.
