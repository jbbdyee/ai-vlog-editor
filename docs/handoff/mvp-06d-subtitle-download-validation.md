# MVP-06D 자막 선택·다운로드 계약과 검증

## 계약

- 기존 `GET /projects/{project_id}/renders/{render_id}/download`는 자막 없는 `final.mp4`를 그대로 제공한다.
- 새 `GET /projects/{project_id}/renders/{render_id}/subtitled/download`는 별도 `final-subtitled.mp4`만 제공한다. 응답은 `video/mp4`, 파일명은 `{render_id}-subtitled.mp4`다.
- `GET /projects/{project_id}/rendering`은 `hard_subtitle_status` (`NOT_STARTED`, `AVAILABLE`, `NO_SUBTITLES`, `NOT_CONFIGURED`, `SUBTITLE_FAILED`, `FAILED`, `MISSING`), 안전한 오류 코드, 다운로드 가능 여부와 URL을 제공한다. `SUBTITLE_FAILED`는 SRT 생성 실패, `FAILED`는 하드 자막 렌더 실패, `MISSING`은 렌더 기록에 있던 파일이 더 이상 유효하지 않은 경우다.
- 경로는 서버가 프로젝트·렌더 ID로 구성하며, 완료 기록의 파일 경로가 정확히 일치하고 비어 있지 않을 때만 다운로드한다. 잘못된 ID는 422, 없는 프로젝트/완료 기록은 404, 아직 완료되지 않은 렌더는 409, 자막 파일이 없으면 `SUBTITLED_RENDER_NOT_FOUND` 404다. 이전에 완료된 렌더는 같은 프로젝트에서 후속 렌더가 진행 중이어도 기존 계약대로 접근할 수 있다.
- Streamlit은 기본 영상과 한국어 자막 적용 영상을 구분해 표시한다. 자막 적용 결과가 없으면 그 다운로드 버튼을 비활성화한다. 다운로드 직전 상태를 다시 확인한다.
- 완료 기록은 프로세스 메모리에만 있다. 서버 재시작 후 남은 파일만으로 다운로드 가능하다고 판단하지 않는다. 프로젝트·렌더 연결 검증은 사용자 인증이나 소유권 검증이 아니다. 인증 없는 공개 배포는 범위 밖이다.

## 검증과 한계

- API 계약 테스트는 합성 MP4 바이트를 사용해 두 파일 다운로드, 파일명/MIME, 자막 없음·환경 미설정·실패, 진행 중·없는 ID·다른 프로젝트, 파일 누락·안전하지 않은 경로를 확인한다.
- 프론트엔드 테스트는 상태 응답 검증, 두 다운로드 준비와 자막 적용 버튼 활성/비활성화를 확인한다. 기존 렌더 API와 프론트엔드 테스트를 함께 실행한다.
- MVP-06C-2B의 합성 MP4/SRT 하드 자막 생성 검증을 재사용하며 렌더 알고리즘은 변경하지 않았다. 외장하드의 실제 촬영 영상, 장시간 렌더, 긴 자막 가독성, 여러 클립 경계 동기화는 아직 검증하지 못했다. P1~P3 Ground Truth와 평가 계약은 변경하지 않았다.
- Windows `.venv`의 FFmpeg를 PATH에 추가한 전체 백엔드 테스트는 534개 실행, 실패 0개, 33개 건너뜀이다. 프론트엔드 테스트는 64개 실행, 실패 0개다. 관련 렌더·하드 자막·06D 테스트는 37개 실행, 실패 0개, 2개 건너뜀이다. 이 두 테스트는 Docker와 검증된 로컬 글꼴이 필요한 합성 하드 자막 재생성 검사다. 이 환경에서 두 의존성을 확인하지 못해 실행하지 않았으며, 06C-2B의 이전 검증 기록으로만 해당 생성 경로를 뒷받침한다.
