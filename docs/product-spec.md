# AI Vlog Editor Product Specification

> Working product name: **Cutory** (WIP)
>
> Status: MVP v1 초기 개발
>
> 이 문서는 제품의 장기 방향과 이미 합의된 경계를 설명한다. 현재 구현 범위는 `mvp-v1-spec.md`를 따른다.

## 1. 제품 정의

AI Vlog Editor는 사용자가 촬영 중 남긴 편집 의도와 촬영 후 수정 요청을 바탕으로 긴 원본 영상의 탐색부터 실제 편집까지 돕는 개인화 영상 편집 서비스다.

핵심 원칙은 다음과 같다.

> 사용자의 창작 판단은 남기고, 반복적인 탐색과 편집 노동은 AI에게 맡긴다.

역할은 다음처럼 나눈다.

```text
User = Creative Decision
AI   = Search / Reasoning / Execution
```

시스템은 편집 구간을 텍스트로 추천하는 데서 끝나지 않고 실제 영상 결과물을 생성해야 한다.

## 2. 대상 사용자와 문제

초기 사용자는 다음 조건에 해당하는 개인 브이로그 제작자다.

- 어떤 순간을 살리고 싶은지는 스스로 판단할 수 있다.
- 긴 원본을 다시 보며 해당 장면을 찾는 데 많은 시간을 쓴다.
- 전문 편집 도구의 타임라인을 세밀하게 조작하는 일을 줄이고 싶다.

핵심 문제는 창작 판단의 부재가 아니라, 이미 내린 판단을 다시 찾아 실행해야 하는 반복 노동이다.

## 3. 핵심 사용자 흐름

```text
촬영
→ 촬영 중 음성 편집 메모
→ 영상 업로드
→ 영상·오디오 분석
→ STT와 타임스탬프
→ 편집 의도 탐지
→ 대상 장면 탐색
→ 편집 계획 및 실제 영상 생성
→ 사용자 확인
→ 자연어 수정 요청
→ 해석 결과 확인
→ 수정 적용
→ 최종 영상
→ 장기 확장: 내러티브 편집과 멀티플랫폼 숏폼 재가공
```

AI가 자연어 요청을 해석한 경우 바로 실행하지 않고, 사용자가 해석 결과를 확인한 뒤 적용하는 UX를 지향한다.

## 4. 제품 기능

### 4.1 촬영 중 음성 편집 메모

사용자는 촬영을 멈추지 않고 다음과 같은 메모를 남긴다.

- “AI야 방금 장면 꼭 살려줘.”
- “이 부분은 짧게 써줘.”
- “여기부터는 빼도 돼.”

MVP v1은 첫 번째 고정 표현과 “방금” 참조에 집중한다.

### 4.2 장면 탐색과 실제 컷 생성

시스템은 메모의 타임스탬프를 찾고, 메모가 가리키는 구간을 선택해 FFmpeg로 실제 영상 파일을 생성한다.

### 4.3 자연어 기반 수정

사용자는 결과 영상에 대해 장면의 길이, 포함 여부, 순서 등을 자연어로 수정 요청할 수 있다. 장기적으로 요청은 검증 가능한 Edit Operation Schema로 변환한다. 스키마는 아직 미결정이다.

### 4.4 개인화

반복적인 사용자 선택과 수정으로 컷 길이, 자막 스타일, 영상 템포 등의 선호를 반영한다. 메모리 구조와 저장 범위는 아직 미결정이다.

### 4.5 Narrative Edit Planner

후보 장면을 단순 연결하지 않고 역할과 관계를 해석해 영상의 흐름을 계획한다.

- 장면 선택과 생략
- 장면 순서
- 장면별 길이
- 도입·사건·반응·마무리 구조

입출력 스키마, LLM/VLM 사용 방식, 평가 지표는 실험 전 확정하지 않는다.

### 4.6 멀티플랫폼 숏폼 재가공

완성된 브이로그의 맥락과 원본 장면을 이용해 Shorts, Reels 등 숏폼 편집안을 만든다.

```text
Long-form video and edit timeline
→ Scene / Narrative Analysis
→ Highlight Candidates
→ Short-form Edit Plan
→ Auto Reframe and Captions
→ Platform Output Profile
→ Rendered Short-form Video
```

플랫폼 규격 준수, 인코딩, 실제 렌더링은 결정적인 코드가 담당한다. LLM/VLM은 장면 의미, 훅, 맥락 보존, 짧은 이야기 구성에 사용될 수 있다. 최종 MP4만 재분석하기보다 원본 클립과 기존 편집 타임라인을 함께 사용하는 방향을 우선 검토한다.

아직 결정하지 않은 항목:

- 플랫폼별 길이와 화면 비율 정책
- 자동 Crop/Reframe 방식
- 자막과 음악 정책
- Hook과 플랫폼별 Narrative 차이
- 자동 게시 여부
- 품질 평가 방법

## 5. 단계별 로드맵

1. **MVP Baseline** — 음성 메모, STT, 고정 시간 구간, 실제 컷
2. **Scene Retrieval Improvement** — Baseline 실패를 바탕으로 장면 경계와 의미 검색 개선
3. **Conversational Editing** — 자연어 수정 요청을 편집 작업으로 변환
4. **Personalization** — 사용자 선택과 수정 이력을 다음 편집에 반영
5. **Narrative Editing** — 여러 장면을 하나의 이야기 흐름으로 구성
6. **Multi-platform Short-form** — 긴 영상을 플랫폼별 숏폼으로 재가공
7. **Agent Workflow Review** — 동적 재계획이 실제로 필요해진 경우에만 검토

## 6. 기술의 역할 경계

| 영역 | 역할 | MVP v1 |
| --- | --- | --- |
| 일반 코드 | 업로드, 파일 검증, 시간 계산, FFmpeg, IoU, 평가 | 사용 |
| STT | 음성을 텍스트와 타임스탬프로 변환 | 사용, 엔진 미정 |
| Embedding | Transcript/Scene 의미 검색 | 제외 |
| LLM | 복합 편집 의도 구조화, Narrative Planning | 제외 |
| VLM | 행동·물체·표정 등 시각적 의미 분석 | 제외 |
| Agent | 실행 중 다음 행동과 도구를 동적으로 선택 | 제외 |

Agent는 LLM과 동일한 개념이 아니다. 순서가 정해진 처리 단계는 일반 워크플로우로 구현한다.

## 7. 개인정보 원칙

- 초기에는 개인 테스트 영상을 사용하고 로컬 처리를 우선한다.
- 원본 영상과 음성은 GitHub에 올리지 않는다.
- 평가의 재현 근거는 Ground Truth, Metric, 결과, Failure Analysis로 남긴다.
- 외부 AI API를 도입하기 전에 전송 데이터, 보관 정책, 비용을 검토한다.
- 실제 사용자 대상 서비스 전에는 삭제 정책, 접근 제어, 동의 UX, 저장 암호화를 별도로 설계한다.

## 8. 제품 성공 판단

- 긴 원본을 다시 탐색하는 시간을 실제로 줄이는가?
- 사용자의 편집 의도를 보존하는가?
- 텍스트 조언이 아니라 실제 결과물을 만드는가?
- Baseline보다 개선됐음을 측정할 수 있는가?
- 추가 기술의 필요성이 실패 사례로 증명됐는가?

## 9. 미결정 사항

- STT 엔진과 Local/Cloud 실행 방식
- Timestamp 정밀도 기준
- “방금”의 최적 탐색 방식
- VLM과 Embedding 도입 시점 및 모델
- Edit Operation Schema
- Narrative Planner 입출력과 평가
- 사용자 선호 Memory 구조
- 숏폼 플랫폼별 편집 정책
- 저장소, 배포, DB 등 운영 인프라
